How should AI-native software
be engineered?

AgentForge is an open, vendor-neutral engineering platform — a working gateway, a portable context spec, and a governed provenance you can read, fork, and extend.

→ playground read the spec
i. The Cathedral

Governance before implementation.

Every sprint ships the same way: a requirements document, an ADR recording the decision, an implementation with tests, CI validation, and release notes. Twenty-one governed milestones — each one reproducible from a fresh clone, each one auditable from the decision register.

This is deliberate. The hardest part of AI-native engineering is not code; it is trust. Trust in what was decided, why, when, by whom, and whether the decision still holds. AgentForge treats that as a first-class artifact:

constitutioncharterADRsRFCsrepo-mapagents

ii. The Bazaar

Vendor-neutral by construction.

One OpenAI-compatible /v1 surface. Three provider adapters behind it — a deterministic mock, a keyless ollama path for local open-weights, and an OpenRouter path for cloud frontier models. Same API, same normalizer, same streaming pipeline. You choose where the intelligence comes from.

Both remote and local paths are live-verified — Sprint 19 against real OpenRouter, Sprint 20 against a real Ollama daemon on a developer machine. The vendor-neutral promise is demonstrated, not declared.

AICS

The AgentForge Context Specification — a portable, filesystem-anchored project context that humans and AI tools both read. Validate it from the CLI, or from the in-browser WASM validator.

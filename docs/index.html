i. The Cathedral

Governance before implementation.

Every sprint ships the same way: a requirements document, an ADR recording the decision, an implementation with tests, CI validation, and release notes. Twenty-one governed milestones — each one reproducible from a fresh clone, each one auditable from the decision register.

This is deliberate. The hardest part of AI-native engineering is not code; it is trust. Trust in what was decided, why, when, and whether the decision still holds. AgentForge treats that as a first-class artifact, anchored to the filesystem — readable by humans and AI tools alike:

ii. The Bazaar

Vendor-neutral by construction.

One OpenAI-compatible /v1 surface. Three provider adapters behind it — a deterministic mock, a keyless Ollama path for local open-weights, and an OpenRouter path for cloud frontier models. Same API, same normalization, same streaming pipeline — you choose where the intelligence comes from.

Both remote and local paths are live-verified — Sprint 19 against real OpenRouter, Sprint 20 against a real Ollama daemon on a developer machine. The vendor-neutral promise is demonstrated, not declared.

The platform has three pillars

Each one is a real artifact with real tests — not a roadmap bullet point.

i.

The Gateway

Dependency-free Python stdlib HTTP service. OpenAI-compatible /v1, streaming, CORS, structured logging — 136 offline tests, zero external dependencies.

apps/gateway · ADR-0002
ii.

AICS

The AgentForge Context Specification — a portable, filesystem-anchored project context that humans and AI tools both read. Validate from the CLI, or from the in-browser WASM validator.

specs/aics-v0.1 · ADR-0005
iii.

The CLI

Validate, scaffold, explain, and diagnose AICS contexts from the terminal — validate-context, init-context, explain-context, doctor. Same checks CI runs on every push.

apps/cli · ADR-0003
